# Рабочий контекст: генератор «Кодекс → ЦМК»

## Статус для продолжения

- Рабочий проект — **`webinar_cmk_generator/`** (GUI 1.3); `webinar_generator/` — прежний отдельный генератор «Кодекса». Не затирать один другим.
- Последняя поставка **`webinar-generator-cmk-proxmox.zip`**, 33 файла, 229 944 байта, SHA‑256 `acb4a061c0ee57f8c872234c0bcfccb759b520861dbf4064fe821899abada91c`. Архив собран, проверен распаковкой и представлен в диалоге. Он включает `webinar_cmk_generator/Proxmox-LXC.md`. Подготовленный ответ был отмечен остановленным; сохранена доступная часть, наличие архива подтверждено отдельно по файлу.
- **Ничего не создано и не установлено на Proxmox пользователя:** нет доступа к его узлу; фактические CTID, IP, bridge и storage не сообщены. Адрес `192.168.1.50` и CTID `120` — примеры. Пользователь выбрал **новый** LXC и **прямо по IP**, не SSH-туннель для браузера. Следующий шаг, если он продолжит запуск: создать контейнер через Proxmox UI или Shell, узнать его CTID/IP, передать релиз и выполнить установку по инструкции. После запуска проверить обе службы и HTTPS с компьютера клиента, затем привязать новый токен и отправить тест из панели. Не выдавать песочницу или UI preview за его LXC.
- **Linux VPS** — отдельный уже подготовленный вариант: `webinar-generator-cmk-vps.zip` + `VPS-Linux.md`, loopback и SSH-туннель. Сетевые настройки на реальном VPS пользователя не подтверждены. Автозапуск в контейнере обеспечит systemd плюс **Start at boot** самого CT.
- Реальная отправка Telegram не подтверждена. Переданный ранее тестовый токен не перенесён; перевыпустить в BotFather, вводить новый токен в защищённую панель. Доступ к чату по токену не подразумевается: нужно связать конкретного получателя.

## Назначение и принятые требования

1. Веб-сайт «Кодекса» даёт расписание; Word оформляется **от имени ЦМК** по фирменному образцу — сохранить шапку, контакты ЦМК и анкету, не переносить контакты «Кодекса» и не перезаписывать оригинальный эталон. Сайт и Dropbox генератором не меняются, формы регистрации не отправляются. «Смотреть программу» ведёт на исходную карточку, не в предпросмотр Word.
2. Каталог, поиск, периоды, сканирование одной карточки или цепочки, сохранение сформированного Word, отображение новых карточек. В том числе для **одной** выбранной карточки показывать одновременно «Скачать Word» и «Скачать ZIP». Для нескольких — общий ZIP и отдельные ссылки. В ZIP отдельная явная папка с названием и одноимённым DOCX:

   ```text
   18 декабря - Оплата труда медицинских работников в 2027 году/
   └── 18 декабря - Оплата труда медицинских работников в 2027 году.docx
   ```

   Точное имя для `/med` задаёт `file_title` по ключу `2026-12-18/med`. DOCX в папке идентичен прямой выгрузке. Свежие ссылки на ZIP и Word действуют до часа/перезапуска; «Сохранённый Word» из SQLite остаётся после рестарта. «Сформировано» — Word записан в историю, а не обязательно скачан. Старые скачанные файлы не импортируются. «К подготовке» — Word ещё нет; «Новое» — карточка добавлена после исходного набора и Word ещё нет.
3. Telegram — полный обход **07:00, 13:30 и 20:00 МСК**, с сохранением результата и очереди; отправлять только впервые найденные текущие и будущие карточки (дата, тема, ссылка). Начальное заполнение известными карточками не рассылает их. Очередь при ошибке не пропадает; подтверждённые отправки не повторяются. Планировщик проверяет в минуту слота, не догоняет пропуски задним числом. Отдельный CLI `watchdog.py` — альтернатива, не запускать параллельно со встроенным worker на той же БД. Браузер можно закрыть, службу — нет.
4. Веб-панель «Мониторинг»: привязка/перепривязка личного чата одноразовым кодом, тест, отмена, отвязка, ручная проверка, включение/пауза. По умолчанию расписание выключено. После успешной тестовой отправки появляется `telegram.json`. `CMK_TELEGRAM_TOKEN` и `CMK_TELEGRAM_CHAT_ID` в окружении имеют приоритет и не меняются из UI. Токен не возвращается в статусе. Для CLI доступны `--connect`, `--test`, `--once`, `--chat-id`, `--data-dir`.
5. Порт можно назначать и менять. В локальном/VPS режиме по умолчанию `127.0.0.1:7860`; `gui.py --set-port PORT` и «Настройки сервера» сохраняют `1024..65535`, вступает в силу после рестарта. Разовый `--port` блокирует редактирование через UI. Для SSH-туннеля после смены поменять целевой порт. В режиме LXC порт HTTPS принадлежит Caddy и меняется из консоли: `cmk-lan-config status`, `cmk-lan-config port 9443`, `cmk-lan-config ip НОВЫЙ_IP`, `cmk-lan-config password`.

| `webinar_cmk_generator/{README.md,VPS-Linux.md,Proxmox-LXC.md,requirements.txt}` | команды и документация, Python 3.10+ |
| `webinar_cmk_generator/{Запустить GUI.cmd,Мониторинг Telegram.cmd,_run.cmd}` | Windows-лаунчеры (общая venv, CRLF) |
| `webinar_generator/`, `programmy-vebinarov/` | исходники прежней версии «Кодекса» и 9 готовых Word; не подменять ЦМК |
| `.work/` | рабочие исходники экспериментов, копии эталонов, сохранённая разметка, документы/рендеры и QA. Это не установочный комплект. Скрипты патчей `modify_gui.py`, `update_gui.py` и `update_ui.py` уже были применены; повторно не запускать. |

`history.sqlite3` хранит последний каталог, программы, порт и состояние слотов/отправок. `event_key` — дата + URL path. Новый запуск без базы делает seed снимка без уведомлений. Папка данных: `--data-dir` / `CMK_DATA_DIR`; по умолчанию Windows `%LOCALAPPDATA%\CMKWebinars`, macOS `~/Library/Application Support/CMKWebinars`, Linux `${XDG_STATE_HOME:-$HOME/.local/state}/cmk-webinars`, в systemd `/var/lib/cmk-webinars`. SQLite heartbeat/lease и фиксация слота защищают от параллельной проверки. Для копии реальной истории остановить процессы и сохранить базу отдельно. Тестовые базы, токен и приватные TLS-ключи в перенос не включены.

**Локально:** `python gui.py` после установки `requirements.txt` в venv; Windows — `Запустить GUI.cmd`. Обычное администрирование требует loopback клиента и сервера, локальный `Host` без прокси-заголовков и точный `Origin` для записи. `--host 0.0.0.0` без LAN-конфига — режим просмотра/основной работы, без административного управления и встроенного worker. Старый внешний preview был остановлен; повторно запускать только при необходимости.

**VPS:** `/opt/cmk-webinars/.venv/bin/python`, служебный пользователь `cmk-webinars`, данные `/var/lib/cmk-webinars`, адрес `127.0.0.1:7860` по умолчанию, доступ через SSH-туннель. Порт — из истории, после изменения `systemctl restart cmk-webinars`. Публичное открытие порта не требуется.

**Proxmox:** новый непривилегированный Debian 12/13 LXC, без Docker, `nesting` и отключения AppArmor. `bash deploy/install-lxc.sh --ip ФАКТИЧЕСКИЙ_IP --port 8443` в интерактивной root-консоли LXC ставит две службы. Внутренний GUI — `127.0.0.1:17860`, не открывать наружу. Caddy слушает только выбранный IPv4, допускает частные IPv4, Basic Auth с bcrypt, HTTPS по TCP (HTTP/1.1, HTTP/2), отклоняет неавторизованных, не пересылает заголовок `Authorization` в GUI. Защищённый административный запрос проверяется по `Host`, переданному Caddy внутреннему ключу и HTTPS-протоколу; POST — ещё и по точному `Origin`. Не отключать это ради обхода ошибки. Пароль отдельный, логин по умолчанию `cmk`. У внешнего прокси `/etc/cmk-lan`, приватные данные Caddy в `/var/lib/cmk-lan-proxy`; только публичный `…/caddy/pki/authorities/local/root.crt` переносится доверенным каналом. Сверить SHA‑256, импортировать на клиенте, не обходить TLS-предупреждение. Закрепить IP, не делать проброс в интернет, при необходимости ограничить TCP-порт нужной подсетью. При смене порта история, привязка Telegram и CA остаются, службы перезапускаются; предусмотрен откат параметров при неудаче.

## Релизы и что фактически проверено

- `webinar-programs-2026.zip` — 9 программ прежнего генератора; `webinar-generator.zip` — его CLI и материалы. ЦМК: `webinar-generator-cmk.zip` — CLI (7 файлов), `webinar-generator-cmk-gui.zip` — GUI (18), `webinar-generator-cmk-watchdog.zip` — мониторинг (24), `webinar-generator-cmk-vps.zip` — VPS (27), `webinar-generator-cmk-proxmox.zip` — итоговая LAN-поставка (33). Старые архивы не заменяют последний для LXC. Набор QA из 16 DOCX/PDF в `.work/chain/` не является ранее выданной поставкой ЦМК.
- Исторический полный живой обход обнаружил 16 карточек; разовый watchdog от 18.11.2026 не прислал уведомления, новых карточек после seed не было. Проверены генерация `/tpk`, `/med`, бланк и рендер. UI проверяли на desktop и мобильных размерах, включая 320–390 px, и выгрузку одного/нескольких документов.
- Повторные тесты `PYTHONPATH=webinar_cmk_generator python .work/watchdog/test_flow.py` (5/5, имитация Telegram) и `PYTHONPATH=webinar_cmk_generator python .work/vps/check_web.py` (4/4, происхождение запросов, резерв слота, порт и рестарт) прошли. Linux unit для VPS проходил sandbox-smoke с systemd. Для CI/воспроизведения использовать тестовую папку данных, без реального токена.
- Proxmox-поставка проверена на **тестовом стенде в изолированном сетевом пространстве**, не на реальном Proxmox: Caddy Debian 2.6.2 и два отдельных пользователя процессов, фактический TLS для частного IP, в Chromium — доверенный импортированный CA без игнорирования TLS. Проверены Basic Auth, доступ к каталогу, отказ неверному Origin, управление расписанием из браузера, точные выгрузки `/med`, сохранённый DOCX после рестарта, отказ занятому порту, смена `8443 → 9443` с тем же CA и закрытием старого порта. `default_sni` нужен для клиента при соединении по IP без SNI. `systemd-analyze verify` проверил шаблоны обеих служб и LXC override; сам установщик внутри реального Proxmox LXC не проходил. Детали — `.work/proxmox/full_lan_qa.py`, сопутствующие скрипты и `Proxmox-LXC.md`.
- Дальнейшая проверка на узле: `pct status CTID`, `pct exec CTID -- ip -4 -br addr`; внутри `cmk-lan-config status`, `systemctl is-active cmk-webinars cmk-lan-proxy`; при ошибках диагностировать через `journalctl -u cmk-webinars -u cmk-lan-proxy -n 50 --no-pager`. Перед отправкой логов исключить секреты. Убедиться, что HTTPS открывается на рабочем компьютере и расписание включается после тестовой доставки. [Справка Proxmox VE о pct](https://pve.proxmox.com/pve-docs/pct.1.html).

`ФАЙЛЫ.csv` в архиве перечисляет фактически перенесённые файлы с размерами и SHA‑256. Рабочие HTML, документы, тесты и скриншоты включены; не включены системные профили/кэши LibreOffice и браузера, логи установки зависимостей, дубли распаковки старых релизов и временные БД. Полный дословный архив ранней переписки не входил в доступные данные, поэтому `01-ТЕКСТ-ЧАТА.md` явно отделяет доступный текст от ретроспективы.
