# Формирование документов — локальное тестовое приложение

PHP-приложение для подготовки писем по снимку Единой книги ведомств. Интерфейс сохраняет визуальный стиль `/Arena/Формирование актов`. Приложение рассчитано на локальный тестовый запуск в Ubuntu LXC.

## Быстрый просмотр в Arena

Из корня пакета:

```sh
sh ./start_preview.sh
```

Сервер по умолчанию слушает `0.0.0.0:8765`; порт можно переопределить через `PORT=8766`. Для этого preview используется `project/public/` как единственный web-root, а данные и рабочие файлы сохраняются в `docgen_handoff/storage/`, вне него. Preview не устанавливает системные зависимости и не заменяет LXC-установку.

## Установка в Ubuntu LXC

Скопируйте или распакуйте **весь пакет** в LXC, затем запустите установщик от root:

```sh
sudo sh ./install_ubuntu.sh
```

Скрипт устанавливает PHP 8.1+, нужные PHP-расширения и LibreOffice Writer, копирует приложение в `/opt/docgen-handoff/app`, создаёт приватное хранилище `/var/lib/docgen`, включает systemd-службу `docgen.service` и просит войти по паролю администратора. Ubuntu 18.04/20.04 и Debian 10/11 со стандартными пакетами PHP ниже 8.1 не поддерживаются: установщик завершится до установки пакетов. Используйте новый LXC на Ubuntu 24.04 LTS (PHP 8.3) или Debian 12 (PHP 8.2); Ubuntu 22.04 (PHP 8.1) также проходит минимальную проверку версии. Если переменная `DOCGEN_ADMIN_PASSWORD` не задана, установщик генерирует пароль и показывает его в конце. Пароль администратора хранится в системе только в виде хеша в `/etc/docgen/app.env`.

Параметры установщика можно задать переменными окружения:

- `DOCGEN_INSTALL_DIR` — корень установки, по умолчанию `/opt/docgen-handoff`;
- `DOCGEN_STORAGE_DIR` — приватные данные приложения, по умолчанию `/var/lib/docgen`;
- `DOCGEN_PORT` — порт, по умолчанию `8080`;
- `DOCGEN_BIND` — адрес привязки, по умолчанию `0.0.0.0`;
- `DOCGEN_ADMIN_PASSWORD` — задать начальный пароль (не менее 12 символов), вместо случайного.

Управление службой и журналы:

```sh
sudo systemctl status docgen.service
sudo journalctl -u docgen.service -f
sudo systemctl restart docgen.service
```

Приложение использует HTTP без TLS. Оставляйте порт доступным только из доверенной локальной сети или добавьте HTTPS/туннель; **не публикуйте сервис в Интернет**. При настройке собственного firewall разрешайте подключение только нужному клиенту/подсети. Изменение пароля администратора: обновить `DOCGEN_ADMIN_PASSWORD_HASH` в `/etc/docgen/app.env` (создать хеш командой `php -r 'echo password_hash(stream_get_contents(STDIN), PASSWORD_DEFAULT), PHP_EOL;'`, передав пароль через stdin), затем перезапустить службу.

## Возможности

- Наборы/регионы, поиск по полям, выбор записей вручную или по фильтру, пагинация.
- Редактирование карточки адресата. Автоматические формы ФИО и должности — только подсказки; проверьте и исправьте их до формирования.
- Если «Полное наименование для письма» в карточке не заполнено, при формировании документов и переменных письма используется «Наименование по книге / ЕГРЮЛ». Значение не подставляется из DaData: поле остаётся ручным, подсказка показана в таблице и в карточке адресата.
- Блоки «Как пользоваться тестовым приложением» и «Шаблон письма: имя файла, получатели, текст» свёрнуты в аккордеоны. Менеджер очереди открывается во всплывающем окне с той же страницей внутри, отдельный URL `queue.php` остаётся для прямой ссылки. Карточка адресата использует аккуратную сетку в три колонки, длинные поля занимают две колонки, а падежи и результаты сверки выравниваются по ширине.

- В книге есть отдельный набор «ТЕСТ» со 100 вымышленными организациями. У всех в поле «Основной email» стоит `docgen@cmkcenter.online` — он предназначен для безопасной обкатки формирования писем, очереди и отправки без риска разослать тест реальным адресатам.
- Ручная сверка руководителей с DaData по отмеченным записям: запрос по ИНН и, если заполнен, КПП; сравнение ФИО и должности из книги с руководителем из ответа ЕГРЮЛ. Несовпадение ФИО подсвечивается, расхождение должности помечается отдельно. Данные не заменяются автоматически; результаты сохраняются в приватном хранилище, а при изменении карточки помечаются устаревшими. Если КПП отсутствует и ответ сообщает о нескольких филиалах, результат помечается неоднозначным и филиал наугад не выбирается. При запуске сверки учитывается тариф/лимит DaData.
- API-ключ DaData вводится вручную в настройках приложения, хранится за web-root с правами `0600`, маскируется и не возвращается браузеру. Автопроверок нет; один ручной запуск обрабатывает только отмеченные записи.
- Для выбранных в списке организаций доступна кнопка «Обновить через DaData»: после ручного запроса открывается диалог со списком полей ответа DaData. Пользователь сам сопоставляет каждое поле с существующей колонкой книги или создаёт новую колонку, видит список «было → стало» и только после проверки нажимает «Сохранить карточки». До этого нажатия ни одна карточка не изменяется. Полное наименование из `name.full_with_opf` не загружается автоматически — оно попадает в книгу только при явном выборе этого сопоставления.
- В результате ручной сверки показывается дата вступления руководителя в должность из `data.management.start_date`. Если ФИО не совпадает, появляется кнопка «Подставить ФИО из DaData»: она заполняет именительный падеж в карточке только после нажатия и требует сохранения карточки вручную. После изменения карточки старый результат помечается «Нужна повторная сверка» — это ожидаемо, повторите сверку для отмеченных записей.
- В блоке автоматического склонения у ФИО скрыт дательный падеж, а в блоке «Должность для обращения» показан только дательный. Обращение «Уважаемый/Уважаемая,» определяется по отчеству и имени и подставляется автоматически, если поле не редактировалось вручную; при неопределённом поле задайте его сами.
- Импорт `.xlsx` с предварительным просмотром листов/строк и подтверждением; экспорт всей базы, текущего фильтра или отмеченных строк в книгу с отдельным листом на раздел. В XLSX включаются внутренний ID и название раздела для безопасного повторного импорта.
- Импорт работает как объединение: обновляет по внутреннему ID либо по уникальной паре ИНН/КПП, новые строки добавляет в выбранный/создаваемый раздел, неоднозначные совпадения пропускает. Пустые ячейки сохраняют прежнее значение по умолчанию; очистку можно включить отдельно. Перед импортом создаётся приватная резервная копия (последние 10 копий хранятся вне web-root).
- Колонки можно добавлять через интерфейс для всех разделов; они появляются в таблице и карточках. Разделы можно создавать в верхнем списке наборов; строки добавляются через Excel-импорт.
- DOCX-шаблоны на PHPWord, коды полей вида `{НазваниеКолонки}` и `${НазваниеКолонки}`. Примерный DOCX встроен; пользовательские DOCX можно загрузить и сохранить в библиотеку шаблонов.
- **Менеджер шаблонов** (кнопка рядом с «Выбрать сохранённый шаблон») и поле «Имя выбранного шаблона» прямо в блоке шаблона: переименовать сохранённый шаблон (файл не меняется), «Сохранить как копию…» под своим именем, заменить DOCX-файл, удалить шаблон вместе с его письмом. У копии сохраняется своё письмо и HTML-дизайн, если они были у исходного шаблона; у встроенного примера имя не меняется, но с него можно снять копию. В списке видны пометки «своё письмо» и «HTML-дизайн».
- Встроенный HTML/CSS-редактор. Сохранённый HTML-шаблон формирует PDF; внешний сетевой контент и исполняемые элементы удаляются перед конвертацией.
- Письмо настраивается **отдельно для каждого шаблона**: имя вложенного файла, «Кому», CC, тема, текст и HTML-дизайн письма хранятся в `templates/letters.json` приватного хранилища. Общий блок «Шаблон письма» остаётся значением по умолчанию: шаблон без своей копии читает общие значения и получает собственную копию при первом сохранении, остальные шаблоны это не затрагивает. Для ещё не сохранённого шаблона и примера действуют общие значения.
- **HTML-дизайн письма** — это оформление тела письма (табличная вёрстка, preheader, кнопки), а не PDF-документ: PDF/DOCX остаётся вложением. Дизайн можно вставить кодом, загрузить готовым `.html`-файлом (до 1 МБ, с подтверждением замены), вставить пример или посмотреть превью с данными выбранной записи. Перед отправкой из дизайна удаляются скрипты, iframe, обработчики `on*`, внешние `src` и `@import`; ссылки в письме остаются кликабельными, а в PDF-конвертации — нет. Коды вида `{Фамилия И.О.}` проверяются при сохранении: неизвестные коды отклоняются с их списком, а подстановки рассылок вида `{{UnsubscribeUrl}}` показываются предупреждением.
- Отправка всегда `multipart/alternative`: к HTML-дизайну прилагается текстовая версия (собственное поле, текст письма или автоматически собранный из HTML текст). Письмо без текстовой версии нельзя ни отправить, ни поставить на автоотправку — менеджер очереди помечает его `pill failed` «нет текстовой версии», а карточка письма подсказывает заполнить поле. Пример дизайна — `docs/letter-design-template.html`; проверки — `cd project && php tests/letter_html_test.php`.
- PDF формируется локально через LibreOffice. Для DOCX-шаблона создаются PDF и DOCX; для HTML-шаблона — PDF. Сформированные файлы остаются доступны по отдельности в очереди; ZIP содержит результат пакета и действует 24 часа.
- При формировании документов рядом со строкой «Готовим PDF и DOCX для N выбранных записей…» показывается мини-лог: этап, номер текущей карточки из N, название организации и последние 8 событий. Лог обновляется опросом сервера каждые 600 мс; на долгой генерации видно, какая именно карточка обрабатывается сейчас.
- Формирование создаёт **пачку** (например, «МИНЗДРАВ — 89 писем»). На главной странице показываются только пачки, ожидающие ручной проверки: откройте аккордеон, проверьте письма, отметьте подтверждение и выберите «Поставить в ручную очередь» либо «В расписание (автоотправка)». Второй вариант требует явного дополнительного подтверждения; по умолчанию остаётся ручная отправка по одному письму.
- Отдельная страница `queue.php` — менеджер очереди: пачки в ручной очереди, в расписании и завершённые, список писем, ошибки, кнопки остановки и повтора ошибочных. На главной остаются только пачки на ручную проверку. Для просмотра конкретного письма из менеджера есть ссылка на карточку проверки. В менеджере можно поставить пачку на паузу и снять с неё, переместить выше/ниже (порядок влияет на автоотправку) и удалить пачку вместе с письмами после явного подтверждения. В Ubuntu страница открывается по адресу `http://<ip-сервера>:8080/queue.php`: встроенный PHP-сервер использует `public/index.php` как роутер, который явно отдаёт этой странице менеджер.
- Отправка «как вручную»: темп ограничен 1–6 письмами в минуту на ящик (mail.ru считает быстрее — рассылкой), к интервалу добавляется случайная задержка (по умолчанию 0–20 с). По расписанию письма уходят только в окне (по умолчанию 09:00–18:00), при желании — только по рабочим дням. На ответ почтового сервиса «слишком часто» (`421 4.7.0` / ratelimit) ящик ставится на паузу 30 минут, письмо остаётся в расписании, автоотправка не «долбит» сервер; ручная отправка возвращает понятный ответ 429. Дневной лимит на ящик (0 — без ограничения, до 300) считает и ручные, и автоматические письма; в менеджере очереди видно «отправлено сегодня из N». Ручная отправка одного письма из карточки окном и дневным лимитом не блокируется — это осознанное действие оператора.
- Лимит отправки задаётся в менеджере отдельно для каждого SMTP-ящика: 1–6 писем в минуту, по умолчанию 1. Разные ящики отправляют одновременно, каждый своим потоком и со своим лимитом: например, `doc1@mail.ru` и `doc2@mail.ru` могут отправлять свои пачки параллельно. Если для ящика не задан собственный лимит, используется лимит по умолчанию. Планировщик `docgen-mailer.timer` запускает `cron_send.php` раз в минуту; координатор группирует письма по ящикам и запускает отдельного воркера для каждого ящика, соблюдая интервал внутри потока. Если письмо не отправлено, оно помечается ошибочным, а пачка продолжает отправку остальных; ошибочные письма можно повторить из менеджера.
- По умолчанию поле `Основной email` используется как «Кому», `Доп./старые email` — как CC. В блоке «Шаблон письма» эти адреса можно заменить своими выражениями с переменными. Адреса извлекаются и дедуплицируются, но старый/непроверенный адрес остаётся на ручной проверке перед отправкой. Если основной адрес отсутствует или не распознаётся, получателя можно внести вручную в очереди.
- Редактор «Шаблон письма» относится к выбранному шаблону (общие значения видны остальным как значения по умолчанию): имя вложенного файла без расширения, «Кому», CC, тема и текст письма задаются строками с кодами вида `{Фамилия И.О.}`. Переменная `{Наименование файла}` содержит имя шаблона без расширения, поэтому в имени вложения не появляется `.docx.docx`. Под полями показан список доступных переменных из колонок книги и текущего шаблона; код вставляется в последнее редактируемое поле по нажатию. Выбранный там SMTP-ящик подставляется в общий селектор «От кого» как значение по умолчанию, но итоговый ящик подтверждается вручную перед формированием очереди. Результат правится в карточке письма; автоматической отправки нет. Во вкладке «HTML-дизайн письма» кнопки «Загрузить HTML-файл», «Вставить пример» и превью с данными выбранной записи заполняют этот же шаблон; поле «Текстовая версия» можно оставить пустым — тогда текст соберётся из HTML, но перед отправкой его стоит прочитать в карточке письма.
- Поддерживается несколько SMTP-ящиков. В «Настройках SMTP» можно добавить, переименовать и удалить ящик; пароль каждого хранится отдельно в приватном файле с правами `0600` и не возвращается в API. При формировании очереди в панели инструментов выбирается ящик отправки — выбор сохраняется в каждом элементе очереди и используется только при ручной отправке этого письма. Старые настройки с одним ящиком автоматически становятся ящиком «Основной».
- SMTP host, порт, шифрование, логин, пароль и данные отправителя задаются через UI. Пароль SMTP не включён в исходники и не возвращается в API: он хранится в приватном файле под каталогом хранения, права `0600`, вне web-root. Кнопка «Проверить SMTP» подключается к серверу, используя **текущие значения формы** (в том числе введённый пароль), и ничего не сохраняет; время ожидания ответа при этой проверке ограничено 8 секундами, а сам запрос в браузере — 20 секундами (отправка писем из очереди использует обычный таймаут PHPMailer). Обе кнопки («Проверить SMTP» и «Сохранить настройки») показывают статус и блокируются на время запроса. Перед сетевым подключением PHP освобождает файл сессии, поэтому проверка не блокирует остальные запросы; встроенный сервер запускается с несколькими worker'ами.
- Исходящие письма проходят mail-tester на 10/10: SPF, DKIM (2048), DMARC `p=quarantine`, rDNS и черные списки чистые. HELO/EHLO отправляется доменом отправителя (например, `cmkcenter.ru`), а не именем контейнера `docgen`, поэтому SpamAssassin не ставит `SPF_HELO_NONE`. Текстовая версия не содержит HTML-тегов; `List-Unsubscribe` намеренно не добавляется — он нужен только массовым рассылкам, а официальное письмо отписки не имеет.
- Исходящие письма не добавляют `X-Mailer` с версией библиотеки; `Message-ID` формируется с доменом из адреса «От кого», а не с коротким именем контейнера. Для релея `mail.cmkcenter.ru` публичные A/PTR согласованы: `185.231.244.230` → `mail.cmkcenter.ru`.
- Блок «Резервная копия: конфигурация и база» выгружает ZIP с книгой адресатов, структурой таблиц, правками карточек, результатами сверки, настройками SMTP/письма/рассылки и сохранёнными шаблонами. Пароли SMTP и API-ключ DaData добавляются только по отдельной галочке; пароль администратора и `app.env` не выгружаются. Загрузка ZIP сначала показывает список файлов и требует явного подтверждения; перед заменой автоматически сохраняется ZIP текущего состояния. Восстановление книги адресатов пишется в приватный `records.json` и не перезаписывает файл из Git. Ссылки на архивы действуют 24 часа.
- В LXC включён парольный вход и CSRF-защита POST-запросов. В Arena preview без настроенного `DOCGEN_ADMIN_PASSWORD_HASH` вход отключён; не используйте открытый preview как публичный сервер.

### Генератор программ вебинаров «Кодекс → ЦМК»

Отдельная страница `webinar.php` (кнопка «Генератор вебинаров» в шапке главной) собирает программы вебинаров ЦМК из карточек web-kodeks.ru. Код живёт в собственной папке `webinars/` и не смешивается с формированием писем: общие только вход по паролю, CSRF и приватный каталог хранения.

- Каталог строится полным обходом витрины по цепочке «следующий вебинар»; карточка содержит дату, время, ведущих, программу и условия участия. В интерфейсе есть поиск, период, вкладки «Все / Новые / Сформированные», метка «Новое» и история сформированных программ.
- Word формируется по утверждённому бланку ЦМК (`webinars/assets/layout-cmk.docx`): 28 абзацев и 3 таблицы, шапка, ведущие, программа, условия участия и анкета заполняются из карточки. Текст документов сверен с эталоном (16 карточек, 16 документов).
- «Скачать Word» отдаёт один файл `дд месяца - Название.docx`; «Скачать ZIP» — папку `дд месяца - Название/файл.docx`. Для пачки формируется общий архив `Программы ЦМК — дд.мм.гггг–дд.мм.гггг.zip` и отдельные Word-файлы. Ссылки живут час, история сформированных Word хранится в приватном каталоге.
- Редактор ручных формулировок (короткое имя файла, выгода, аудитория, «с кем», темы, закрывающая строка) сохраняется в приватном `webinars/editorial.json` и применяется при следующем формировании.
- Бланк заменяется загрузкой DOCX в панели; структура проверяется по обязательным разделам, иначе файл отклоняется. Кнопка сброса возвращает утверждённый бланк из поставки.
- Telegram-мониторинг новых карточек: проверки в 07:00, 13:30 и 20:00 МСК, очередь уведомлений без повторов, привязка бота по одноразовому коду, тестовое сообщение. Рассылки нет — только скачивание файлов.
- Планировщик запускается общим таймером `docgen-mailer.timer` через `cron_send.php` (раз в минуту); пропущенный слот не догоняется. Ручная проверка: `php webinars_tick.php --force`. Проверки — `cd project && php tests/webinar_test.php`.

## Конвертация и зависимости

В пакете уже включены `vendor/` и `composer.lock`: PHPWord 1.4, Morphos 3.2 и PHPMailer 6.12. В Ubuntu нужны PHP 8.1+ с `zip`, `dom`, `xml`, `xmlwriter`, `mbstring`, `gd`, `ctype`, `openssl`, а также `libreoffice-writer`. Без openssl недоступен транспорт `ssl://` и SMTP по порту 465/587 не подключится. LibreOffice используется в headless-режиме; без него PDF не будет создан и приложение сообщит об ошибке. Тестовая отправка требует действующих SMTP-параметров. Для ручной сверки DaData нужен исходящий HTTPS-доступ до `suggestions.dadata.ru`, включённый `allow_url_fopen` и действующий API-ключ. Excel-импорт поддерживает `.xlsx` до 20 МБ, 50 листов, 20 000 строк суммарно и 250 колонок на лист; распакованный архив ограничен 100 МБ, заголовок — 120, значение — 5 000 символов. Читаются значения ячеек/сохранённые значения формул (Excel на сервере их не пересчитывает); формат ячеек, даты, изображения, комментарии и макросы не переносятся. Перед повторным импортом той же новой строки рекомендуется выгрузить её из приложения, чтобы использовать выданный внутренний ID.

Ограничения и восстановление: для записей без ID и валидной пары ИНН/КПП невозможно безопасно определить, что строка уже импортировалась; повторная загрузка может добавить её ещё раз. Совпадение ИНН/КПП, дублирующееся в исходной базе, без ID пропускается как неоднозначное. Резервная копия создаётся перед реальным изменением пользовательских таблиц и правок карточек; хранятся последние 10 копий. Через блок резервной копии можно вручную восстановить конфигурацию и базу из ZIP; автоматического отката, автоматического восстановления и переименования/удаления колонок или разделов нет. Делайте отдельные регулярные копии всего приватного `DOCGEN_STORAGE_DIR`; на время импорта не запускайте параллельные изменения из нескольких сессий.

- `data/demo_overrides.json` — только подтверждённое дополнительное значение для `guber-0037`.

- `tests/letter_html_test.php` — автономные проверки письма и дизайна (`php tests/letter_html_test.php`, хранилище во временной папке).
- `tests/webinar_test.php` — автономные проверки генератора вебинаров (`php tests/webinar_test.php`): сверка разбора и текста 16 документов с эталоном, ZIP-структура, редактура, уведомления и слоты МСК.
- `features.php` и `index.php` — приложение и API; `public/index.php` — тонкий web-entrypoint. Остальные файлы проекта недоступны напрямую через web-root.

Настройки рассылки хранятся в `mailing.json`: `lettersPerMinute` — лимит по умолчанию, `accountLimits` — лимиты по ID SMTP-ящиков. Состояние каждого ящика и блокировки его потока хранятся отдельно в приватном `mailer-accounts/`; старый общий `mailer-cron-state.json` используется только как начальная точка при первом запуске новой схемы.

`{Полное наименование}` отсутствует в исходной таблице. Не переносите «Губернатору Астраханской области» на другие регионы: подтверждённое значение относится только к `guber-0037`. Если переменная шаблона для конкретной записи не заполнена, такая запись пропускается с объяснением ошибки, а не дополняется догадкой.

## Ручной тест-план

1. Убедиться, что по умолчанию выбран источник «Все наборы», выбор адресатов пуст.
2. Проверить XLSX-экспорт всей базы, текущего фильтра и отмеченных строк: открыть книгу, убедиться, что листы соответствуют разделам, а ИНН/КПП с ведущими нулями не изменились.
3. В тестовой копии приложения добавить колонку и пустой раздел через UI. Импортировать многолистовой `.xlsx`: проверить предварительный просмотр, сопоставление листов, обновление по ID и уникальному ИНН/КПП, пропуск неоднозначных дублей, сохранение пустых ячеек и создание нового раздела/строк. Убедиться, что перед импортом создана резервная копия, а после импорта экспорт снова открывается в Excel.
4. Выбрать 1–2 записи с заполненными данными и сделать DOCX→PDF; проверить в очереди PDF и DOCX, если шаблон DOCX.
5. В «Сверка руководителей · DaData» вставить API-ключ, сохранить и убедиться, что он скрыт. Отметить одну тестовую запись и вручную нажать «Сверить руководителей по ИНН»; проверить ФИО/должность в таблице и карточке. Повторно сверить запись с изменённым руководителем — старый результат должен стать устаревшим.
6. Создать и сохранить HTML-шаблон с `{Регион}` и `{ФИО}`, выбрать его и проверить PDF.
7. Сохранить тестовые SMTP-настройки, проверить соединение, затем сформировать 1 адресата. Убедиться, что `Основной email` стоит в «Кому», а дополнительный email — в CC.
8. Открыть PDF, поправить адреса/тему/текст, отметить подтверждение и отправить только один тестовый элемент на контролируемый адрес.
9. Проверить, что другие элементы очереди не отправлены автоматически.
10. Загрузить DOCX-шаблон, во вкладке «HTML-дизайн письма» вставить `docs/letter-design-template.html`, сохранить письмо — в блоке должна появиться пометка «свои настройки шаблона». Переключиться на другой шаблон и убедиться, что у него остались общие значения, а возврат к первому восстанавливает его дизайн.
11. Сформировать очередь по шаблону с дизайном и открыть карточку письма: проверить вкладку «HTML-дизайн» (ссылки кликабельны, preheader не виден) и непустую текстовую версию. Сформировать письмо без текстовой версии — автоотправка должна блокироваться, а менеджер очереди — показать «нет текстовой версии».
12. Проверить, что неизвестный код в дизайне (например, `{НетТакого}`) не сохраняется, а `{{UnsubscribeUrl}}` даёт предупреждение при сохранении.
13. Настроить «Настройки рассылки» в менеджере очереди: 1 письмо в минуту, дневной лимит 30–50, окно 09:00–18:00, задержка 20 с, «только по рабочим дням». Поставить пачку в расписание и убедиться, что вне окна она ждёт, а в окне письма идут с неровными интервалами. Проверить, что после ответа 421 письмо остаётся в расписании, а ящик получает паузу 30 минут.
14. Открыть «Менеджер шаблонов»: переименовать шаблон («Вебинар 11.12.2028 · тарифы»), убедиться, что список и подпись в блоке шаблона обновились, а письмо шаблона осталось. Снять копию — новая строка должна получить своё письмо и HTML-дизайн. Заменить DOCX-файл — имя, получатели и дизайн сохраняются, а невалидный файл отклоняется с сообщением. Удалить шаблон — он исчезает вместе с письмом, остальные не меняются.
15. Открыть «Генератор вебинаров» из шапки главной: увидеть каталог карточек, найти вебинар поиском, переключить вкладки и период. Нажать «Обновить расписание» — список должен совпасть с сайтом, а новые карточки получить метку «Новое».
16. Сформировать одну программу: «Скачать Word» даёт `дд месяца - Название.docx`, «Скачать ZIP» — архив с папкой `дд месяца - Название`. Отметить несколько карточек и проверить общий архив `Программы ЦМК — дд.мм.гггг–дд.мм.гггг.zip` и отдельные Word.
17. Изменить в редакторе короткое имя файла, выгоду и темы, сохранить и сформировать программу заново — правки должны попасть в документ.
18. Загрузить в панели другой DOCX: чужой файл отклоняется с объяснением, утверждённый бланк принимается; кнопка сброса возвращает бланк из поставки.
19. Привязать Telegram-бота по коду из панели и отправить тестовое сообщение. Затем выполнить `cd project && php webinars_tick.php --force` и убедиться, что проверка прошла, а повторный запуск не дублирует уведомления.
20. Проверить, что `webinar.php` и `queue.php` открываются по прямым адресам и что после входа возвращают на ту же страницу.
