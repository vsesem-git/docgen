# Формирование документов — локальное тестовое приложение

PHP-приложение для подготовки писем по снимку Единой книги ведомств. Интерфейс сохраняет визуальный стиль `/Arena/Формирование актов`. Приложение рассчитано на локальный тестовый запуск в Ubuntu LXC.

## Быстрый просмотр в Arena

Из корня пакета:

```sh
sh ./start_preview.sh
```

Сервер по умолчанию слушает `0.0.0.0:8765`; порт можно переопределить через `PORT=8766`. Для этого preview используется `project/public/` как единственный web-root, а данные и рабочие файлы сохраняются в `docgen_handoff/storage/`, вне него. Preview не устанавливает системные зависимости и не заменяет LXC-установку.

## Установка в Ubuntu LXC

Скопируйте или распакуйте **весь пакет** в LXC, затем запустите установщик от root:

```sh
sudo sh ./install_ubuntu.sh
```

Скрипт устанавливает PHP 8.1+, нужные PHP-расширения и LibreOffice Writer, копирует приложение в `/opt/docgen-handoff/app`, создаёт приватное хранилище `/var/lib/docgen`, включает systemd-службу `docgen.service` и просит войти по паролю администратора. Ubuntu 18.04/20.04 и Debian 10/11 со стандартными пакетами PHP ниже 8.1 не поддерживаются: установщик завершится до установки пакетов. Используйте новый LXC на Ubuntu 24.04 LTS (PHP 8.3) или Debian 12 (PHP 8.2); Ubuntu 22.04 (PHP 8.1) также проходит минимальную проверку версии. Если переменная `DOCGEN_ADMIN_PASSWORD` не задана, установщик генерирует пароль и показывает его в конце. Пароль администратора хранится в системе только в виде хеша в `/etc/docgen/app.env`.

Параметры установщика можно задать переменными окружения:

- `DOCGEN_INSTALL_DIR` — корень установки, по умолчанию `/opt/docgen-handoff`;
- `DOCGEN_STORAGE_DIR` — приватные данные приложения, по умолчанию `/var/lib/docgen`;
- `DOCGEN_PORT` — порт, по умолчанию `8080`;
- `DOCGEN_BIND` — адрес привязки, по умолчанию `0.0.0.0`;
- `DOCGEN_ADMIN_PASSWORD` — задать начальный пароль (не менее 12 символов), вместо случайного.

Управление службой и журналы:

```sh
sudo systemctl status docgen.service
sudo journalctl -u docgen.service -f
sudo systemctl restart docgen.service
```

Приложение использует HTTP без TLS. Оставляйте порт доступным только из доверенной локальной сети или добавьте HTTPS/туннель; **не публикуйте сервис в Интернет**. При настройке собственного firewall разрешайте подключение только нужному клиенту/подсети. Изменение пароля администратора: обновить `DOCGEN_ADMIN_PASSWORD_HASH` в `/etc/docgen/app.env` (создать хеш командой `php -r 'echo password_hash(stream_get_contents(STDIN), PASSWORD_DEFAULT), PHP_EOL;'`, передав пароль через stdin), затем перезапустить службу.

## Возможности

- Наборы/регионы, поиск по полям, выбор записей вручную или по фильтру, пагинация.
- Редактирование карточки адресата. Автоматические формы ФИО и должности — только подсказки; проверьте и исправьте их до формирования.
- Ручная сверка руководителей с DaData по отмеченным записям: запрос по ИНН и, если заполнен, КПП; сравнение ФИО и должности из книги с руководителем из ответа ЕГРЮЛ. Несовпадение ФИО подсвечивается, расхождение должности помечается отдельно. Данные не заменяются автоматически; результаты сохраняются в приватном хранилище, а при изменении карточки помечаются устаревшими. Если КПП отсутствует и ответ сообщает о нескольких филиалах, результат помечается неоднозначным и филиал наугад не выбирается. При запуске сверки учитывается тариф/лимит DaData.
- API-ключ DaData вводится вручную в настройках приложения, хранится за web-root с правами `0600`, маскируется и не возвращается браузеру. Автопроверок нет; один ручной запуск обрабатывает только отмеченные записи.
- В результате ручной сверки показывается дата вступления руководителя в должность из `data.management.start_date`. Если ФИО не совпадает, появляется кнопка «Подставить ФИО из DaData»: она заполняет именительный падеж в карточке только после нажатия и требует сохранения карточки вручную. После изменения карточки старый результат помечается «Нужна повторная сверка» — это ожидаемо, повторите сверку для отмеченных записей.
- В блоке автоматического склонения у ФИО скрыт дательный падеж, а в блоке «Должность для обращения» показан только дательный. Обращение «Уважаемый/Уважаемая,» определяется по отчеству и имени и подставляется автоматически, если поле не редактировалось вручную; при неопределённом поле задайте его сами.
- Импорт `.xlsx` с предварительным просмотром листов/строк и подтверждением; экспорт всей базы, текущего фильтра или отмеченных строк в книгу с отдельным листом на раздел. В XLSX включаются внутренний ID и название раздела для безопасного повторного импорта.
- Импорт работает как объединение: обновляет по внутреннему ID либо по уникальной паре ИНН/КПП, новые строки добавляет в выбранный/создаваемый раздел, неоднозначные совпадения пропускает. Пустые ячейки сохраняют прежнее значение по умолчанию; очистку можно включить отдельно. Перед импортом создаётся приватная резервная копия (последние 10 копий хранятся вне web-root).
- Колонки можно добавлять через интерфейс для всех разделов; они появляются в таблице и карточках. Разделы можно создавать в верхнем списке наборов; строки добавляются через Excel-импорт.
- DOCX-шаблоны на PHPWord, коды полей вида `{НазваниеКолонки}` и `${НазваниеКолонки}`. Примерный DOCX встроен; пользовательские DOCX можно загрузить и сохранить в библиотеку шаблонов.
- Встроенный HTML/CSS-редактор. Сохранённый HTML-шаблон формирует PDF; внешний сетевой контент и исполняемые элементы удаляются перед конвертацией.
- PDF формируется локально через LibreOffice. Для DOCX-шаблона создаются PDF и DOCX; для HTML-шаблона — PDF. Сформированные файлы остаются доступны по отдельности в очереди; ZIP содержит результат пакета и действует 24 часа.
- Формирование создаёт **пачку** (например, «МИНЗДРАВ — 89 писем»). На главной странице показываются только пачки, ожидающие ручной проверки: откройте аккордеон, проверьте письма, отметьте подтверждение и выберите «Поставить в ручную очередь» либо «В расписание (автоотправка)». Второй вариант требует явного дополнительного подтверждения; по умолчанию остаётся ручная отправка по одному письму.
- Отдельная страница `queue.php` — менеджер очереди: пачки в ручной очереди, в расписании и завершённые, список писем, ошибки, кнопки остановки и повтора ошибочных. На главной остаются только пачки на ручную проверку. Для просмотра конкретного письма из менеджера есть ссылка на карточку проверки.
- Лимит отправки настраивается в менеджере: 1–60 писем в минуту, по умолчанию 1. Планировщик `docgen-mailer.timer` запускает `cron_send.php` раз в минуту; за запуск обрабатывается не больше лимита писем с соблюдением интервала. Если письмо не отправлено, оно помечается ошибочным, а пачка продолжает отправку остальных; ошибочные письма можно повторить из менеджера.
- По умолчанию поле `Основной email` используется как «Кому», `Доп./старые email` — как CC. В блоке «Шаблон письма» эти адреса можно заменить своими выражениями с переменными. Адреса извлекаются и дедуплицируются, но старый/непроверенный адрес остаётся на ручной проверке перед отправкой. Если основной адрес отсутствует или не распознаётся, получателя можно внести вручную в очереди.
- Редактор «Шаблон письма» общий для всех DOCX/HTML-шаблонов: имя вложенного файла без расширения, «Кому», CC, тема и текст письма задаются строками с кодами вида `{Фамилия И.О.}`. Под полями показан список доступных переменных из колонок книги и текущего шаблона (включая `{Наименование файла}`); код вставляется в последнее редактируемое поле по нажатию. Выбранный там SMTP-ящик подставляется в общий селектор «От кого» как значение по умолчанию, но итоговый ящик подтверждается вручную перед формированием очереди. Результат правится в карточке письма; автоматической отправки нет.
- Поддерживается несколько SMTP-ящиков. В «Настройках SMTP» можно добавить, переименовать и удалить ящик; пароль каждого хранится отдельно в приватном файле с правами `0600` и не возвращается в API. При формировании очереди в панели инструментов выбирается ящик отправки — выбор сохраняется в каждом элементе очереди и используется только при ручной отправке этого письма. Старые настройки с одним ящиком автоматически становятся ящиком «Основной».
- SMTP host, порт, шифрование, логин, пароль и данные отправителя задаются через UI. Пароль SMTP не включён в исходники и не возвращается в API: он хранится в приватном файле под каталогом хранения, права `0600`, вне web-root. Кнопка «Проверить SMTP» подключается к серверу, используя **текущие значения формы** (в том числе введённый пароль), и ничего не сохраняет; время ожидания ответа при этой проверке ограничено 8 секундами, а сам запрос в браузере — 20 секундами (отправка писем из очереди использует обычный таймаут PHPMailer). Обе кнопки («Проверить SMTP» и «Сохранить настройки») показывают статус и блокируются на время запроса. Перед сетевым подключением PHP освобождает файл сессии, поэтому проверка не блокирует остальные запросы; встроенный сервер запускается с несколькими worker'ами.
- В LXC включён парольный вход и CSRF-защита POST-запросов. В Arena preview без настроенного `DOCGEN_ADMIN_PASSWORD_HASH` вход отключён; не используйте открытый preview как публичный сервер.

## Конвертация и зависимости

В пакете уже включены `vendor/` и `composer.lock`: PHPWord 1.4, Morphos 3.2 и PHPMailer 6.12. В Ubuntu нужны PHP 8.1+ с `zip`, `dom`, `xml`, `xmlwriter`, `mbstring`, `gd`, `ctype`, `openssl`, а также `libreoffice-writer`. Без openssl недоступен транспорт `ssl://` и SMTP по порту 465/587 не подключится. LibreOffice используется в headless-режиме; без него PDF не будет создан и приложение сообщит об ошибке. Тестовая отправка требует действующих SMTP-параметров. Для ручной сверки DaData нужен исходящий HTTPS-доступ до `suggestions.dadata.ru`, включённый `allow_url_fopen` и действующий API-ключ. Excel-импорт поддерживает `.xlsx` до 20 МБ, 50 листов, 20 000 строк суммарно и 250 колонок на лист; распакованный архив ограничен 100 МБ, заголовок — 120, значение — 5 000 символов. Читаются значения ячеек/сохранённые значения формул (Excel на сервере их не пересчитывает); формат ячеек, даты, изображения, комментарии и макросы не переносятся. Перед повторным импортом той же новой строки рекомендуется выгрузить её из приложения, чтобы использовать выданный внутренний ID.

Ограничения и восстановление: для записей без ID и валидной пары ИНН/КПП невозможно безопасно определить, что строка уже импортировалась; повторная загрузка может добавить её ещё раз. Совпадение ИНН/КПП, дублирующееся в исходной базе, без ID пропускается как неоднозначное. Резервная копия создаётся перед реальным изменением пользовательских таблиц и правок карточек; хранятся последние 10 копий. В интерфейсе нет кнопки отката/восстановления, автоматического восстановления и переименования/удаления колонок или разделов. Делайте отдельные регулярные копии всего приватного `DOCGEN_STORAGE_DIR`; на время импорта не запускайте параллельные изменения из нескольких сессий.

## Данные и приватные файлы

- `data/records.json` — 1 022 записи (989 основных и 33 архивных).
- `data/demo_overrides.json` — только подтверждённое дополнительное значение для `guber-0037`.
- `samples/letter_example.docx` — исходный DOCX-пример.
- `features.php` и `index.php` — приложение и API; `public/index.php` — тонкий web-entrypoint. Остальные файлы проекта недоступны напрямую через web-root.
- Вне web-root хранятся правки карточек, шаблоны, очередь, файлы PDF/DOCX, SMTP-настройки/секреты, API-ключ DaData, результаты сверки руководителей, пользовательские разделы/колонки/импортированные строки (`table_data.json`), временные XLSX-файлы импорта и до 10 резервных копий перед Excel-импортом.

`{Полное наименование}` отсутствует в исходной таблице. Не переносите «Губернатору Астраханской области» на другие регионы: подтверждённое значение относится только к `guber-0037`. Если переменная шаблона для конкретной записи не заполнена, такая запись пропускается с объяснением ошибки, а не дополняется догадкой.

## Ручной тест-план

1. Убедиться, что по умолчанию выбран источник «Все наборы», выбор адресатов пуст.
2. Проверить XLSX-экспорт всей базы, текущего фильтра и отмеченных строк: открыть книгу, убедиться, что листы соответствуют разделам, а ИНН/КПП с ведущими нулями не изменились.
3. В тестовой копии приложения добавить колонку и пустой раздел через UI. Импортировать многолистовой `.xlsx`: проверить предварительный просмотр, сопоставление листов, обновление по ID и уникальному ИНН/КПП, пропуск неоднозначных дублей, сохранение пустых ячеек и создание нового раздела/строк. Убедиться, что перед импортом создана резервная копия, а после импорта экспорт снова открывается в Excel.
4. Выбрать 1–2 записи с заполненными данными и сделать DOCX→PDF; проверить в очереди PDF и DOCX, если шаблон DOCX.
5. В «Сверка руководителей · DaData» вставить API-ключ, сохранить и убедиться, что он скрыт. Отметить одну тестовую запись и вручную нажать «Сверить руководителей по ИНН»; проверить ФИО/должность в таблице и карточке. Повторно сверить запись с изменённым руководителем — старый результат должен стать устаревшим.
6. Создать и сохранить HTML-шаблон с `{Регион}` и `{ФИО}`, выбрать его и проверить PDF.
7. Сохранить тестовые SMTP-настройки, проверить соединение, затем сформировать 1 адресата. Убедиться, что `Основной email` стоит в «Кому», а дополнительный email — в CC.
8. Открыть PDF, поправить адреса/тему/текст, отметить подтверждение и отправить только один тестовый элемент на контролируемый адрес.
9. Проверить, что другие элементы очереди не отправлены автоматически.
